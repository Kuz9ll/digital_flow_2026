## 3.3. Команды импорта в Innovus

Переменные, объявленные в Makefile через `export`, доступны внутри Tcl как элементы `::env`.

Импорт выполняется процедурой `user_init_design`:

```tcl
    # Настройка технологического узла
    if {[info exists ::env(TECH_SIZE)] && $::env(TECH_SIZE) ne ""} {
        set_db design_process_node $::env(TECH_SIZE)
    }

    # Исходные данные и сети питания
    set_db init_netlist_files $::env(ENV_NETLIST)
    set_db init_lef_files     $::env(ENV_LEF_FILES)
    set_db init_power_nets    $::env(ENV_POWER_NETS)
    set_db init_ground_nets   $::env(ENV_GROUND_NETS)
    set_db init_mmmc_files    $::env(ENV_MMMC)

    # Чтение конфигурации анализа и физических библиотек
    read_mmmc $::env(ENV_MMMC)
    read_physical -lef $::env(ENV_LEF_FILES)

    # Чтение netlist и инициализация проекта
    read_netlist $::env(ENV_NETLIST) -top $::env(ENV_DESIGN)
    init_design
```

Команды выполняют следующие действия:

| Команда | Назначение |
| --- | --- |
| `set_db design_process_node` | Задаёт технологический узел для настроек инструмента; не заменяет загрузку PDK |
| `set_db init_*` | Задаёт параметры инициализации |
| `read_mmmc` | Читает конфигурацию режимов и условий анализа |
| `read_physical -lef` | Загружает физические описания из LEF |
| `read_netlist ... -top ...` | Загружает netlist и выбирает верхний модуль |
| `init_design` | Выполняет инициализацию проекта на основе загруженных данных |

# 4. Геометрия floorplan

При создании floorplan задаются размеры блока, область размещения стандартных ячеек и периферийные отступы. Основные понятия этого этапа — **die**, **core**, **rows** и **site**.

## 4.1. Die, core, rows и site

**Die** — внешняя граница проектируемой области. При проектировании целой микросхемы она соответствует границе кристалла, а при реализации отдельного блока — границе этого блока.

**Core** — внутренняя область, предназначенная для размещения стандартных ячеек. Между границами die и core задаются отступы. В этой лабораторной работе периферийная область используется для кольца питания и сигнальных пинов; устанавливать отдельные IO pad cells не требуется.

**Rows** — ряды внутри core, в которых размещаются стандартные ячейки. Ряды задают допустимые положения и ориентации ячеек. Их участки можно удалять, исключая соответствующие области из размещения.

**Site** — базовая единица сетки размещения, описанная в LEF. Она задаёт ширину и высоту места размещения. Ширина стандартной ячейки обычно кратна ширине site; высота обычной однорядной ячейки соответствует высоте ряда.

Таким образом, die определяет внешние размеры блока, core — область размещения логики, rows — организацию рядов, а site — шаг сетки размещения.

## 4.2. Создание floorplan через GUI

В окне настройки floorplan геометрию можно задать двумя способами:

- **через целевую плотность размещения** — инструмент рассчитывает размеры области по площади стандартных ячеек;
- **через явные размеры** — пользователь вводит заранее рассчитанные ширину и высоту.

Основные параметры настройки:

| Параметр | Назначение |
| --- | --- |
| Cell Utilization | Целевая доля площади core, занимаемая стандартными ячейками |
| Aspect Ratio | Соотношение сторон области; порядок сторон следует проверить по обозначениям в окне |
| Core Margins / Offsets | Отступы между границами core и die с каждой стороны |
| Width / Height | Ширина и высота области при явном задании размеров |

### Задание через Cell Utilization

При использовании **Cell Utilization** инструмент рассчитывает размеры core по суммарной площади стандартных ячеек и заданной плотности. Например, значение 50% означает, что суммарная площадь ячеек составляет половину площади core.

Для определения формы области задаётся соотношение сторон, а для формирования периферийной области — отступы между core и die.

### Отступы и проверка результата

Отступы формируют периферийную область между core и die. Её размеры выбирают с учётом расположения кольца питания, сигнальных пинов и технологических ограничений.

## 4.3. Расчёт площади и размеров floorplan

Плотность заполнения показывает, какую долю выбранной области занимает суммарная площадь стандартных ячеек. При расчёте относительно площади core:

$$
U_{core}=\frac{A_{cells}}{A_{core}},
$$

где:

- **U_core** — плотность заполнения core, безразмерная величина; например, 50% соответствует 0.5;
- **A_cells** — суммарная площадь стандартных ячеек, мкм²;
- **A_core** — площадь core, мкм².

### Определение площади ячеек по отчёту синтеза

Для расчёта используйте **отчёт о площади (`report_area`) итоговой схемы после синтеза и оптимизации**, полученный в лабораторной работе №2.

1. Откройте отчёт о площади.
2. Найдите строку своего блока — `blockA` или `blockB`.
3. Определите суммарную площадь ячеек блока. В зависимости от формата отчёта соответствующее поле может называться **Cell Area**, **Instance Area** или **Total Cell Area**.
4. Проверьте единицы измерения. Для получения размеров в мкм площадь должна быть выражена в мкм².

Если отчёт содержит иерархию, используйте итоговую площадь блока **с учётом всех вложенных экземпляров**. Не складывайте её повторно с площадями дочерних модулей: это приведёт к двойному учёту.

Условный пример отчёта:

```text
Instance    Cell Count    Cell Area
----------------------------------
blockA             420     10000.00
```

Если площадь указана в мкм², для этого примера **A_cells = 10 000 мкм²**.

**Cell Count** — количество ячеек, а **Cell Area** — их суммарная площадь. Для расчёта размеров floorplan используется площадь, а не количество.

> Используйте данные для итогового netlist, который импортируется в Innovus. Площадь межсоединений, если она приведена отдельно, в A_cells не включается.

### Расчёт площади core

Для заданной целевой плотности:

$$
A_{core}=\frac{A_{cells}}{U_{core}},
$$

где:

- **A_core** — требуемая площадь core, мкм²;
- **A_cells** — суммарная площадь ячеек из отчёта синтеза, мкм²;
- **U_core** — выбранная целевая плотность в долях единицы.

При плотности 50%:

$$
A_{core}=2A_{cells}.
$$

Здесь **A_core** — площадь core, а **A_cells** — суммарная площадь ячеек; обе величины выражаются в мкм².

При неизменном составе ячеек увеличение площади core уменьшает плотность, а уменьшение площади — повышает её. Эта зависимость показана на рисунке 5.

### Расчёт ширины и высоты core

Одной площади недостаточно для определения формы блока: необходимо выбрать соотношение сторон:

$$
r=\frac{W_{core}}{H_{core}},
$$

где:

- **r** — отношение ширины core к его высоте, безразмерная величина;
- **W_core** — ширина core, мкм;
- **H_core** — высота core, мкм.

По площади и соотношению сторон размеры определяются следующим образом:

$$
W_{core}=\sqrt{rA_{core}},
\qquad
H_{core}=\sqrt{\frac{A_{core}}{r}},
$$

где:

- **W_core**, **H_core** — рассчитываемые ширина и высота core, мкм;
- **A_core** — площадь core, мкм²;
- **r** — выбранное отношение ширины к высоте.

Для квадратного core **r = 1**, поэтому:

$$
W_{core}=H_{core}=\sqrt{A_{core}},
$$

где **W_core** и **H_core** — стороны квадратного core в мкм, а **A_core** — его площадь в мкм².

### Расчёт размеров die

Размеры die определяются добавлением периферийных отступов к размерам core:

$$
W_{die}=W_{core}+m_L+m_R,
$$

$$
H_{die}=H_{core}+m_B+m_T,
$$

где:

- **W_die**, **H_die** — ширина и высота die, мкм;
- **W_core**, **H_core** — ширина и высота core, мкм;
- **m_L**, **m_R** — отступы между core и die слева и справа, мкм;
- **m_B**, **m_T** — отступы между core и die снизу и сверху, мкм.

Отступы выбираются с учётом места для кольца питания, сигнальных пинов и необходимых технологических расстояний.

### Пример расчёта

Исходные данные:

| Параметр | Значение |
| --- | --- |
| Суммарная площадь ячеек A_cells | 10 000 мкм² |
| Целевая плотность U_core | 0.5, или 50% |
| Соотношение сторон r | 1 — квадратный core |
| Отступы m_L, m_R, m_B, m_T | По 10 мкм |

Площадь core:

$$
A_{core}=\frac{10\,000}{0.5}=20\,000\text{ мкм}^2,
$$

где **A_core** — требуемая площадь core.

Ширина и высота core:

$$
W_{core}=H_{core}=\sqrt{20\,000}\approx141.42\text{ мкм},
$$

где **W_core** и **H_core** — размеры квадратного core.

При отступах по 10 мкм с каждой стороны размеры die:

$$
W_{die}=H_{die}\approx141.42+10+10=161.42\text{ мкм},
$$

где **W_die** и **H_die** — ширина и высота die.

Если установлено ограничение **die не менее 200 × 200 мкм**, при сохранении отступов по 10 мкм размеры core составят:

$$
W_{core}=H_{core}=200-10-10=180\text{ мкм},
$$

где **W_core** и **H_core** — размеры core после увеличения die.

Фактическая плотность:

$$
U_{core}=\frac{10\,000}{180\cdot180}\approx0.309=30.9\%,
$$

где **U_core** — отношение площади ячеек к новой площади core.

Таким образом, ограничение минимального размера die может привести к плотности ниже целевой. Отступы в этом примере условные; их допустимость проверяется отдельно.

### Направления металлических слоёв

Для металлических слоёв обычно задают предпочтительное направление трассировки — **горизонтальное или вертикальное**. У соседних слоёв эти направления, как правило, чередуются.

Один из распространённых вариантов:

- нечётные слои — горизонтальное направление;
- чётные слои — вертикальное направление.

Чередование позволяет прокладывать горизонтальные и вертикальные участки на разных слоях и соединять их через vias. Это упорядочивает трассировку и уменьшает число конфликтов между пересекающимися соединениями.

На показанном примере горизонтальные участки создаются на **TopMetal2(7)**, а вертикальные — на **TopMetal1(6)**.

> Соответствие чётности и направления не универсально. Проверяйте предпочтительные направления по технологическому LEF и настройкам инструмента. Числа в скобках в GUI могут обозначать индексы слоёв, а не номера из их названий.

#### Почему для кольца используются разные слои

В данной работе горизонтальные и вертикальные стороны кольца создаются на разных металлических слоях и соединяются через vias.

Использование одного слоя для всего кольца может вызвать следующие трудности:

- **Подключение внутреннего кольца.** Чтобы подвести питание к внутреннему кольцу, необходимо пересечь внешнее. На одном слое такое пересечение соединит VDD и VSS и вызовет короткое замыкание. Для пересечения потребуется переход на другой слой.
- **Ограничения направления проводников.** Некоторые технологии задают строгие ограничения на направление трассировки. На таких слоях часть сторон кольца может нарушать технологические правила. В других технологиях предпочтительное направление является рекомендацией, а не запретом.
- **Занятость трассировочных ресурсов.** Горизонтальные и вертикальные участки на одном слое занимают ресурсы обоих направлений и затрудняют прокладку других соединений на этом слое.

Разделение направлений по двум слоям упрощает построение кольца и подключение к нему других проводников питания.

> Кольцо на одном слое не обязательно имеет большее сопротивление или падение напряжения. Эти характеристики зависят от материала, толщины, ширины и длины проводников, а также расположения точек подключения питания.

## 5.5. Шины питания вдоль рядов

Шины питания проходят вдоль rows и обеспечивают подключение PG-выводов стандартных ячеек к сетям VDD и VSS.

**Rows и шины питания — разные объекты.** Ряд задаёт места размещения ячеек, а шина является металлическим проводником. Создание rows само по себе не означает, что питание подключено.

Для формирования шин и соединения элементов сети питания используется специальная трассировка — **SRoute**.

### Настройка через GUI

Откройте **Route → Special Route…**. В окне **SRoute** на вкладке **Basic** укажите сети в поле **Net(s)**:

`VDD VSS`

На рисунке 10 показано окно настройки специальной трассировки.

![Подключение питания через SRoute](doc/images/Sroute.PNG)

*Рисунок 10 — Окно SRoute: выбор сетей, типов подключаемых объектов и разрешённых слоёв.*

В области **SRoute** выбираются типы объектов, которые необходимо подключить:

| Параметр | Назначение |
| --- | --- |
| Follow Pins | Формирование и подключение шин вдоль рядов по геометрии PG-выводов стандартных ячеек |
| Block Pins | Подключение выводов питания макроблоков |
| Pad Pins | Подключение выводов питания IO-ячеек |
| Pad Rings | Подключение колец питания IO-ячеек |
| Floating Stripes | Подключение неподключённых полос питания |

Для работы с шинами стандартных ячеек используется **Follow Pins**. Остальные параметры выбираются по составу проекта; включать все опции только потому, что они отмечены на скриншоте, не требуется.

В области **Layer Change Control** задаются:

- **Bottom Layer** — нижний разрешённый слой;
- **Top Layer** — верхний разрешённый слой;
- **Allow Layer Change** — разрешение переходов между слоями;
- **Allow Jogging** — разрешение дополнительных изгибов проводников.

Диапазон слоёв должен позволять соединить шины рядов с кольцом или stripes через необходимые vias.

После настройки выполните операцию кнопкой **Apply** или **OK**.

### Проверка результата

После выполнения SRoute проверьте:

- наличие шин питания вдоль rows;
- соответствие шин сетям VDD и VSS;
- соединение шин с кольцом или stripes;
- наличие необходимых vias;
- отсутствие замыканий между VDD и VSS.

Просмотрите сообщения в консоли и log: ошибки необходимо устранить, предупреждения — устранить либо объяснить их причину и влияние на результат.

- порядок разрядов шин соответствует заданному;
- пины не перекрываются между собой и не замыкаются на питание.

> Жёлтый маркер показывает положение порта, но не заменяет проверку геометрии металлического пина. Если пин и проводник питания находятся на одном слое, их пересечение приведёт к замыканию.

## 5.8. Placement blockage

**Placement blockage** задаёт область с ограничениями на размещение ячеек. Например, его можно использовать, чтобы оставить свободное место под будущий макроблок или зарезервировать участок floorplan.

Основные типы ограничений:

| Тип | Назначение |
| --- | --- |
| Hard | Запрещает размещение стандартных ячеек в области |
| Soft | Ограничивает размещение на начальных этапах, но допускает использование области при последующей оптимизации |
| Partial | Ограничивает плотность размещения в области |

Для полного запрета размещения стандартных ячеек используется тип **Hard**.

### Создание и проверка

1. Выберите инструмент создания **Placement Blockage**.
2. Укажите тип **Hard**.
3. Задайте прямоугольную область двумя противоположными углами.
4. Завершите создание объекта.
5. Выберите созданный blockage и проверьте его тип и координаты в свойствах объекта.

Если требуется ограничить область сложной формы, используйте несколько прямоугольных blockages. Например, рамку по периметру можно составить из четырёх прямоугольников.

На рисунке 15 показан прямоугольный placement blockage внутри core. Ряды размещения в этой области сохраняются, но размещение стандартных ячеек запрещено.

![Placement blockage внутри core](doc/images/placement_blk.PNG)

*Рисунок 15 — Пример прямоугольного placement blockage внутри core.*

### Изменение и удаление

Чтобы изменить границы blockage, выберите объект и отредактируйте его геометрию или координаты. Для снятия ограничения удалите сам blockage.

После изменения проверьте, что ограничение действует только в нужной области и не перекрывает участки, предназначенные для размещения.

> Placement blockage не удаляет rows и не запрещает трассировку проводников. Ограничения на прокладку проводников задаются отдельно с помощью **routing blockage**.

### Routing blockage и отличие от placement blockage

**Routing blockage** задаёт область, в которой ограничена трассировка на выбранном слое или нескольких слоях металла. Его используют, чтобы зарезервировать участок для будущих соединений или исключить прокладку проводников через определённую область.

При создании routing blockage необходимо задать:

- границы области;
- слой или набор слоёв металла;
- типы сетей, на которые распространяется ограничение, если такие настройки предусмотрены инструментом.

### Создание и проверка

1. Выберите инструмент создания **Routing Blockage**.
2. Укажите металлические слои, на которых требуется ограничить трассировку.
3. Задайте прямоугольную область двумя противоположными углами.
4. Завершите создание объекта.
5. Выберите созданный blockage и проверьте его границы, слои и параметры в свойствах объекта.

На рисунке 16 показана прямоугольная область routing blockage внутри core. Ряды размещения проходят через эту область и сохраняются.

![Routing blockage внутри core](doc/images/route_clk.PNG)

### Сравнение ограничений

| Объект | Влияние на размещение ячеек | Влияние на трассировку | Удаляет rows? |
| --- | --- | --- | --- |
| Hard placement blockage | Запрещает размещение стандартных ячеек в области | Не задаёт запрета на трассировку | Нет |
| Routing blockage | Не задаёт запрета на размещение | Ограничивает трассировку на выбранных слоях | Нет |
| Cut row | Удаляет доступные места размещения в области | Не задаёт запрета на трассировку | Да |

Чтобы изменить ограничение, отредактируйте границы, набор слоёв или другие свойства routing blockage. Чтобы снять его, удалите сам объект.

> Routing blockage не удаляет уже существующие проводники. Его действие на сигнальную и специальную трассировку, включая сети питания, определяется настройками объекта и инструмента. После создания проверьте эти параметры в свойствах.

**1. Определите площадь ячеек.**

Укажите суммарную площадь стандартных ячеек $A_{\mathrm{cells}}$ в мкм².

**2. Рассчитайте площадь core для плотности 50%.**

$$
A_{\mathrm{core}} = \frac{A_{\mathrm{cells}}}{0.5}
$$

**3. Рассчитайте размеры квадратного core.**

$$
W_{\mathrm{core}} = H_{\mathrm{core}} = \sqrt{A_{\mathrm{core}}}
$$

**4. Выберите отступы между core и die.**

Примите одинаковый отступ $d$ с четырёх сторон. Учитывайте кольцо питания и последующее вырезание rows: часть рядов должна попадать в удаляемую периферийную область.

**5. Рассчитайте размеры die с учётом минимального размера 200 мкм.**

$$
W_{\mathrm{die}} = \max\left(W_{\mathrm{core}} + 2d,\; 200\,\text{мкм}\right)
$$

$$
H_{\mathrm{die}} = \max\left(H_{\mathrm{core}} + 2d,\; 200\,\text{мкм}\right)
$$

**6. Уточните размеры core и фактическую плотность.**

При сохранении выбранных отступов итоговые размеры core составят:

$$
W_{\mathrm{core,final}} = W_{\mathrm{die}} - 2d
$$

$$
H_{\mathrm{core,final}} = H_{\mathrm{die}} - 2d
$$

Фактическая плотность:

$$
U_{\mathrm{core}} =
\frac{A_{\mathrm{cells}}}
{W_{\mathrm{core,final}} \cdot H_{\mathrm{core,final}}}
\cdot 100\%
$$

**7. Задайте рассчитанную геометрию в Innovus.**

- s = 2 мкм;

Округлите значения по технологической сетке. Проверьте соответствие правилам технологии; каждый параметр должен оставаться не больше 20 мкм. 

Создайте **внешнее кольцо VSS** и **внутреннее кольцо VDD**.

Используйте два верхних разрешённых слоя:

- для верхней и нижней сторон — слой с горизонтальным предпочтительным направлением;
- для левой и правой сторон — слой с вертикальным предпочтительным направлением.

В углах соедините участки одной сети через vias. Каждое кольцо должно быть замкнутым.

> Значение o отсчитывается от границы die до внешнего края кольца. Поле Offset в Add Rings задавайте с учётом выбранной опорной границы. Проверьте результат по фактическим координатам проводников.

### 4. Добавьте центральные проводники питания

Создайте два вертикальных проводника:

- слева — VDD;
- справа — VSS.

Задайте:

| Параметр | Требование |
| --- | --- |
| Ширина каждого проводника | w |
| Расстояние между их краями | s |
| Положение пары | Симметрично относительно вертикальной оси die |
| Металлический слой | Используемый для вертикальных сторон кольца |

Каждый проводник должен соединять верхнюю и нижнюю стороны кольца своей сети.


### 5. Вырежьте периферийные участки rows

Удалите периферийные **hard placement blockages**, созданные в задании на 4.

Вырежьте rows под кольцами питания и снаружи них. Между **внутренним краем кольца VDD** и оставшимися rows оставьте зазор **2 мкм** с каждой стороны.

#### Определите ширину области вырезания

$$
t = o + 2w + s + a
$$

где:

- **t** — расстояние от границы die до границы оставшихся rows;
- **o** — отступ от границы die до внешнего края кольца;
- **w** — ширина каждого проводника кольца;
- **s** — расстояние между проводниками VDD и VSS;
- **a = 2 мкм** — зазор от внутреннего края кольца VDD до оставшихся rows.

#### Задайте области вырезания

Используйте фактические координаты die:

- **(x0, y0)** — нижний левый угол;
- **(x1, y1)** — верхний правый угол.

Откройте **Floorplan → Row → Cut Core Row…** и последовательно вырежьте четыре области:

| Область | LLX | LLY | URX | URY |
| --- | --- | --- | --- | --- |
| Слева | x0 | y0 | x0 + t | y1 |
| Справа | x1 − t | y0 | x1 | y1 |
| Снизу | x0 + t | y0 | x1 − t | y0 + t |
| Сверху | x0 + t | y1 − t | x1 − t | y1 |

Все значения задаются в **мкм**.

После вырезания проверьте, что rows сохранились внутри кольца, а зазор до его внутреннего края составляет **не менее 2 мкм**. При привязке границ к сетке размещения округляйте их в сторону увеличения зазора.

> При расчёте floorplan выберите отступ core от die меньше t, чтобы область вырезания пересекала существующие rows.

#### Проверьте результат

- Rows внутри кольца сохранились.
- Участки rows под кольцом и снаружи него удалены.
- Размеры die и core не изменились.
- Кольца и шины питания сохранились, поскольку вырезание rows не удаляет проводники.
- Шины оставшихся rows подключены к соответствующим сетям VDD/VSS.
