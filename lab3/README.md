## 3.3. Команды импорта в Innovus

Переменные, объявленные в Makefile через `export`, доступны внутри Tcl как элементы `::env`.

Импорт выполняется процедурой `user_init_design`:

```tcl
    # Настройка технологического узла
    if {[info exists ::env(TECH_SIZE)] && $::env(TECH_SIZE) ne ""} {
        set_db design_process_node $::env(TECH_SIZE)
    }

    # Исходные данные и сети питания
    set_db init_netlist_files $::env(ENV_NETLIST)
    set_db init_lef_files     $::env(ENV_LEF_FILES)
    set_db init_power_nets    $::env(ENV_POWER_NETS)
    set_db init_ground_nets   $::env(ENV_GROUND_NETS)
    set_db init_mmmc_files    $::env(ENV_MMMC)

    # Чтение конфигурации анализа и физических библиотек
    read_mmmc $::env(ENV_MMMC)
    read_physical -lef $::env(ENV_LEF_FILES)

    # Чтение netlist и инициализация проекта
    read_netlist $::env(ENV_NETLIST) -top $::env(ENV_DESIGN)
    init_design
```

Команды выполняют следующие действия:

| Команда | Назначение |
| --- | --- |
| `set_db design_process_node` | Задаёт технологический узел для настроек инструмента; не заменяет загрузку PDK |
| `set_db init_*` | Задаёт параметры инициализации |
| `read_mmmc` | Читает конфигурацию режимов и условий анализа |
| `read_physical -lef` | Загружает физические описания из LEF |
| `read_netlist ... -top ...` | Загружает netlist и выбирает верхний модуль |
| `init_design` | Выполняет инициализацию проекта на основе загруженных данных |

# 4. Геометрия floorplan

При создании floorplan задаются размеры блока, область размещения стандартных ячеек и периферийные отступы. Основные понятия этого этапа — **die**, **core**, **rows** и **site**.

## 4.1. Die, core, rows и site

**Die** — внешняя граница проектируемой области. При проектировании целой микросхемы она соответствует границе кристалла, а при реализации отдельного блока — границе этого блока.

**Core** — внутренняя область, предназначенная для размещения стандартных ячеек. Между границами die и core задаются отступы. В этой лабораторной работе периферийная область используется для кольца питания и сигнальных пинов; устанавливать отдельные IO pad cells не требуется.

**Rows** — ряды внутри core, в которых размещаются стандартные ячейки. Ряды задают допустимые положения и ориентации ячеек. Их участки можно удалять, исключая соответствующие области из размещения.

**Site** — базовая единица сетки размещения, описанная в LEF. Она задаёт ширину и высоту места размещения. Ширина стандартной ячейки обычно кратна ширине site; высота обычной однорядной ячейки соответствует высоте ряда.

Таким образом, die определяет внешние размеры блока, core — область размещения логики, rows — организацию рядов, а site — шаг сетки размещения.

## 4.2. Создание floorplan через GUI

В окне настройки floorplan геометрию можно задать двумя способами:

- **через целевую плотность размещения** — инструмент рассчитывает размеры области по площади стандартных ячеек;
- **через явные размеры** — пользователь вводит заранее рассчитанные ширину и высоту.

Основные параметры настройки:

| Параметр | Назначение |
| --- | --- |
| Cell Utilization | Целевая доля площади core, занимаемая стандартными ячейками |
| Aspect Ratio | Соотношение сторон области; порядок сторон следует проверить по обозначениям в окне |
| Core Margins / Offsets | Отступы между границами core и die с каждой стороны |
| Width / Height | Ширина и высота области при явном задании размеров |

### Задание через Cell Utilization

При использовании **Cell Utilization** инструмент рассчитывает размеры core по суммарной площади стандартных ячеек и заданной плотности. Например, значение 50% означает, что суммарная площадь ячеек составляет половину площади core.

Для определения формы области задаётся соотношение сторон, а для формирования периферийной области — отступы между core и die.

Отступы формируют периферийную область между core и die. Её размеры выбирают с учётом расположения кольца питания, сигнальных пинов и технологических ограничений.

## 4.3. Расчёт площади и размеров floorplan

Плотность заполнения показывает, какую долю выбранной области занимает суммарная площадь стандартных ячеек. При расчёте относительно площади core:

$$
U_{core}=\frac{A_{cells}}{A_{core}},
$$

где:

- **U_core** — плотность заполнения core, безразмерная величина; например, 50% соответствует 0.5;
- **A_cells** — суммарная площадь стандартных ячеек, мкм²;
- **A_core** — площадь core, мкм².

### Определение площади ячеек по отчёту синтеза

Для расчёта используйте **отчёт о площади (`report_area`) итоговой схемы после синтеза и оптимизации**, полученный в лабораторной работе №2.

1. Откройте отчёт о площади.
2. Найдите строку своего блока — `blockA` или `blockB`.
3. Определите суммарную площадь ячеек блока. В зависимости от формата отчёта соответствующее поле может называться **Cell Area**, **Instance Area** или **Total Cell Area**.
4. Проверьте единицы измерения. Для получения размеров в мкм площадь должна быть выражена в мкм².

Если отчёт содержит иерархию, используйте итоговую площадь блока **с учётом всех вложенных экземпляров**. Не складывайте её повторно с площадями дочерних модулей: это приведёт к двойному учёту.

Условный пример отчёта:

```text
Instance    Cell Count    Cell Area
----------------------------------
blockA             420     10000.00
```

Если площадь указана в мкм², для этого примера **A_cells = 10 000 мкм²**.

**Cell Count** — количество ячеек, а **Cell Area** — их суммарная площадь. Для расчёта размеров floorplan используется площадь, а не количество.

> Используйте данные для итогового netlist, который импортируется в Innovus. Площадь межсоединений, если она приведена отдельно, в A_cells не включается.

### Расчёт площади core

Для заданной целевой плотности:

$$
A_{core}=\frac{A_{cells}}{U_{core}},
$$

где:

- **A_core** — требуемая площадь core, мкм²;
- **A_cells** — суммарная площадь ячеек из отчёта синтеза, мкм²;
- **U_core** — выбранная целевая плотность в долях единицы.

При плотности 50%:

$$
A_{core}=2A_{cells}.
$$

Здесь **A_core** — площадь core, а **A_cells** — суммарная площадь ячеек; обе величины выражаются в мкм².

При неизменном составе ячеек увеличение площади core уменьшает плотность, а уменьшение площади — повышает её. Эта зависимость показана на рисунке 5.

### Расчёт ширины и высоты core

Одной площади недостаточно для определения формы блока: необходимо выбрать соотношение сторон:

$$
r=\frac{W_{core}}{H_{core}},
$$

где:

- **r** — отношение ширины core к его высоте, безразмерная величина;
- **W_core** — ширина core, мкм;
- **H_core** — высота core, мкм.

По площади и соотношению сторон размеры определяются следующим образом:

$$
W_{core}=\sqrt{rA_{core}},
\qquad
H_{core}=\sqrt{\frac{A_{core}}{r}},
$$

где:

- **W_core**, **H_core** — рассчитываемые ширина и высота core, мкм;
- **A_core** — площадь core, мкм²;
- **r** — выбранное отношение ширины к высоте.

Для квадратного core **r = 1**, поэтому:

$$
W_{core}=H_{core}=\sqrt{A_{core}},
$$

где **W_core** и **H_core** — стороны квадратного core в мкм, а **A_core** — его площадь в мкм².

### Расчёт размеров die

Размеры die определяются добавлением периферийных отступов к размерам core:

$$
W_{die}=W_{core}+m_L+m_R,
$$

$$
H_{die}=H_{core}+m_B+m_T,
$$

где:

- **W_die**, **H_die** — ширина и высота die, мкм;
- **W_core**, **H_core** — ширина и высота core, мкм;
- **m_L**, **m_R** — отступы между core и die слева и справа, мкм;
- **m_B**, **m_T** — отступы между core и die снизу и сверху, мкм.

Отступы выбираются с учётом места для кольца питания, сигнальных пинов и необходимых технологических расстояний.

### Пример расчёта

Исходные данные:

| Параметр | Значение |
| --- | --- |
| Суммарная площадь ячеек A_cells | 10 000 мкм² |
| Целевая плотность U_core | 0.5, или 50% |
| Соотношение сторон r | 1 — квадратный core |
| Отступы m_L, m_R, m_B, m_T | По 10 мкм |

Площадь core:

$$
A_{core}=\frac{10\,000}{0.5}=20\,000\text{ мкм}^2,
$$

где **A_core** — требуемая площадь core.

Ширина и высота core:

$$
W_{core}=H_{core}=\sqrt{20\,000}\approx141.42\text{ мкм},
$$

где **W_core** и **H_core** — размеры квадратного core.

При отступах по 10 мкм с каждой стороны размеры die:

$$
W_{die}=H_{die}\approx141.42+10+10=161.42\text{ мкм},
$$

где **W_die** и **H_die** — ширина и высота die.

Если установлено ограничение **die не менее 200 × 200 мкм**, при сохранении отступов по 10 мкм размеры core составят:

$$
W_{core}=H_{core}=200-10-10=180\text{ мкм},
$$

где **W_core** и **H_core** — размеры core после увеличения die.

Фактическая плотность:

$$
U_{core}=\frac{10\,000}{180\cdot180}\approx0.309=30.9\%,
$$

где **U_core** — отношение площади ячеек к новой площади core.

Таким образом, ограничение минимального размера die может привести к плотности ниже целевой. Отступы в этом примере условные; их допустимость проверяется отдельно.

### Фактическая геометрия и плотность

Рассчитанные размеры необходимо согласовать с сеткой размещения: шириной site и высотой rows. После округления следует повторно вычислить плотность по фактической площади core.

Удаление участков rows и создание hard placement blockages уменьшают доступную площадь размещения, но не меняют геометрическую площадь core. Поэтому плотность относительно core и плотность относительно доступной области могут различаться.

> При сравнении ручного расчёта с отчётом инструмента проверяйте, какая площадь используется в знаменателе: площадь core, площадь оставшихся rows или доступная площадь с учётом ограничений размещения.
## 4.4. Предварительная оценка сети питания

Одних размеров die недостаточно, чтобы определить ширину кольца, ширину stripes и шаг их расположения. Для предварительной оценки необходимо связать электрическую нагрузку с геометрией проводников.

### Оценка потребляемого тока

Средний ток можно оценить по мощности блока и напряжению питания:

$$
I_{avg}=\frac{P}{V_{DD}},
$$

где:

- **I_avg** — средний потребляемый ток, А;
- **P** — суммарная мощность блока, Вт;
- **V_DD** — напряжение питания относительно VSS, В.

#### Где взять мощность блока

Откройте отчёт анализа мощности, сформированный в лабораторной работе №2 командой **report_power**. Используйте отчёт для итогового netlist после синтеза и оптимизации.

Найдите суммарную мощность своего блока — `blockA` или `blockB`. Обычно она обозначается как **Total Power**. Если отчёт содержит иерархию, используйте итоговую мощность блока с учётом вложенных экземпляров. Не складывайте её повторно с мощностями дочерних модулей.

Общая мощность включает:

- **Internal Power** — внутреннюю динамическую мощность ячеек;
- **Switching Power** — мощность переключения ёмкостной нагрузки;
- **Leakage Power** — мощность утечки.

Проверьте единицы измерения в отчёте. Перед подстановкой в формулу переведите мощность в ватты: **1 мВт = 0.001 Вт**, **1 мкВт = 0.000001 Вт**.

Напряжение питания возьмите из условий анализа, соответствующих отчёту мощности. Оно должно соответствовать использованному библиотечному углу.

Например, при мощности **12 мВт** и напряжении **1.2 В**:

$$
I_{avg}=\frac{0.012}{1.2}=0.01\text{ А}=10\text{ мА},
$$

где **I_avg** — оценка среднего тока блока.

### Допустимое падение напряжения

Металлические проводники и vias имеют сопротивление. При протекании тока на них возникает падение напряжения — **IR Drop**.

У нагрузки потенциал VDD может оказаться ниже напряжения источника, а потенциал VSS — выше потенциала земли источника. В результате уменьшается напряжение между выводами питания ячеек. Это может увеличить задержки и нарушить работу схемы.

Допустимое уменьшение напряжения задаётся требованиями проекта. Если оно выражено долей номинального напряжения:

$$
\Delta V_{allow}=kV_{DD},
$$

где:

- **ΔV_allow** — допустимое уменьшение напряжения питания у нагрузки, В;
- **k** — допустимая доля потерь, безразмерная величина;
- **V_DD** — номинальное напряжение питания относительно VSS, В.

Например, **k = 0.05** соответствует 5%. При напряжении 1.2 В допустимое уменьшение составит **0.06 В**, или **60 мВ**.

Значение 5% приведено только для примера и не является универсальным требованием.

Общий бюджет потерь распределяется между сетями VDD и VSS:

$$
\Delta V_{VDD}+\Delta V_{VSS}\leq\Delta V_{allow},
$$

где:

- **ΔV_VDD** — падение напряжения от источника VDD до вывода питания нагрузки, В;
- **ΔV_VSS** — повышение потенциала вывода земли нагрузки относительно источника VSS, В;
- **ΔV_allow** — общий допустимый бюджет потерь, В.

Например, из общего бюджета 60 мВ можно предварительно выделить по 30 мВ каждой сети. Затем бюджет каждой сети распределяется между кольцом, stripes, шинами питания рядов и vias.

![Падение напряжения в сети питания](doc/images/power_voltage_drop.png)

*Рисунок 9 — Падение напряжения в VDD, повышение потенциала VSS и распределение общего бюджета потерь.*

Для рассматриваемого пути допустимое эквивалентное сопротивление оценивается как:

$$
R_{max}=\frac{\Delta V_{path}}{I_{path}},
$$

где:

- **R_max** — максимально допустимое эквивалентное сопротивление пути, Ом;
- **ΔV_path** — выделенный этому пути бюджет падения напряжения, В;
- **I_path** — ток через рассматриваемый путь, А.

Например, при токе **10 мА** и бюджете **30 мВ** сопротивление пути должно быть не больше **3 Ом**.

> Ток всего блока нельзя автоматически приписывать каждому проводнику. Для отдельного участка необходимо оценивать ток нагрузки, питание которой проходит через него.

### Сопротивление проводника

Для однородного прямого проводника постоянной ширины:

$$
R_{segment}=R_{\square}\frac{L}{w},
$$

где:

- **R_segment** — сопротивление участка проводника, Ом;
- **R_□** — сопротивление квадрата выбранного слоя металла, Ом/□;
- **L** — длина участка, мкм;
- **w** — ширина участка, мкм.

Отношение L/w показывает число квадратов в проводнике. Длина и ширина должны быть выражены в одинаковых единицах. Сопротивление квадрата берётся из технологических данных для соответствующих условий.

Падение напряжения на участке определяется законом Ома:

$$
\Delta V_{segment}=I_{segment}R_{segment},
$$

где:

- **ΔV_segment** — падение напряжения на участке, В;
- **I_segment** — ток через участок, А;
- **R_segment** — сопротивление участка, Ом.

При неизменном токе увеличение длины повышает сопротивление и падение напряжения, а увеличение ширины уменьшает их.

### Предварительный выбор ширины

Объединяя выражения для сопротивления и падения напряжения, можно оценить минимальную ширину отдельного участка:

$$
w\geq\frac{I_{segment}R_{\square}L}{\Delta V_{segment,allow}},
$$

где:

- **w** — минимальная ширина по упрощённой оценке IR Drop, мкм;
- **I_segment** — ток через рассматриваемый участок, А;
- **R_□** — сопротивление квадрата металла, Ом/□;
- **L** — длина участка, мкм;
- **ΔV_segment,allow** — допустимое падение напряжения, выделенное этому участку, В.

Для расчёта используются следующие данные:

| Величина | Откуда взять |
| --- | --- |
| Ток участка | Из оценки нагрузки, питание которой проходит через участок |
| Длина участка | Из предполагаемой геометрии floorplan |
| Сопротивление квадрата | Из технологических данных выбранного металла |
| Допустимое падение напряжения | Из бюджета, распределённого между элементами сети |

На рисунке 10 показаны параметры проводника, используемые при расчёте.

![Предварительный расчёт ширины проводника](doc/images/power_wire_width.png)

*Рисунок 10 — Длина, ширина и сопротивление участка проводника при оценке падения напряжения.*

#### Пример расчёта

Пусть для отдельного участка приняты следующие условные значения:

| Параметр | Значение |
| --- | --- |
| Ток I_segment | 2 мА = 0.002 А |
| Сопротивление квадрата R_□ | 0.05 Ом/□ |
| Длина L | 200 мкм |
| Допустимое падение ΔV_segment,allow | 10 мВ = 0.01 В |

Тогда:

$$
w\geq\frac{0.002\cdot0.05\cdot200}{0.01}=2\text{ мкм},
$$

где **w** — требуемая ширина рассматриваемого участка.

По этой модели ширина должна быть не менее 2 мкм. Полученное значение округляется вверх до допустимой технологической сетки. После этого необходимо проверить:

- разрешённые ширины выбранного металла;
- расстояния до соседних проводников;
- токовые ограничения;
- возможность размещения необходимого количества vias.

Расчёт предполагает постоянный ток по всей длине участка. Он не учитывает сопротивления vias, остальных частей сети и распределённое подключение нагрузок. Поэтому полученная ширина является начальной оценкой.

### Ограничения по плотности тока

Ширина проводника должна обеспечивать не только допустимое падение напряжения, но и допустимую плотность тока. Длительное протекание чрезмерного тока может привести к **электромиграции** — переносу атомов металла и постепенному повреждению проводника.

Средняя по поперечному сечению плотность тока оценивается как:

$$
J=\frac{I_{segment}}{w t},
$$

где:

- **J** — плотность тока, А/мкм²;
- **I_segment** — ток через рассматриваемый участок, А;
- **w** — ширина проводника, мкм;
- **t** — толщина металла, мкм.

Произведение ширины и толщины определяет площадь поперечного сечения. При неизменном токе увеличение этой площади уменьшает плотность тока.

На рисунке 11 показаны поперечное сечение проводника и направление тока.

![Плотность тока в проводнике](doc/images/power_current_density.png)

*Рисунок 11 — Ширина и толщина проводника, определяющие площадь его поперечного сечения.*

Полученное значение сравнивают с технологическими ограничениями. Они зависят от слоя металла, температуры, требуемого срока службы и характера тока.

Если ограничение задано допустимой плотностью тока, минимальную ширину можно оценить как:

$$
w\geq\frac{I_{segment}}{J_{allow}t},
$$

где:

- **w** — минимальная ширина по ограничению плотности тока, мкм;
- **I_segment** — ток участка, А;
- **J_allow** — допустимая плотность тока, А/мкм²;
- **t** — толщина металла, мкм.

> Технологические ограничения могут задаваться в другой форме, например как допустимый ток на единицу ширины. Используйте единицы и правила проверки, предусмотренные технологией.

#### Проверка vias

Ток между слоями металла проходит через vias. Даже достаточно широкий проводник может иметь ненадёжное соединение, если переходов недостаточно.

Для предварительной оценки при равномерном распределении тока между одинаковыми vias:

$$
N_{via}\geq
\left\lceil\frac{I_{connection}}{I_{via,allow}}\right\rceil,
$$

где:

- **N_via** — минимальное целое число переходов;
- **I_connection** — суммарный ток через соединение слоёв, А;
- **I_via,allow** — допустимый ток одного перехода для рассматриваемых условий, А;
- **⌈…⌉** — округление вверх до целого числа.

Это упрощённая оценка: фактический ток между переходами может распределяться неравномерно. Дополнительно учитываются правила формирования массива vias и размеры охватывающего металла.

Для каждого участка выбранная ширина должна одновременно удовлетворять ограничениям по падению напряжения, плотности тока и геометрическим правилам технологии.

Проверки по среднему, действующему и пиковому току выполняются согласно требованиям технологии. Одной оценки среднего тока блока недостаточно для полной проверки электромиграции.

### Выбор начальной структуры сети

Предварительный выбор сети питания выполняется последовательно:

1. Оцените потребляемый ток и определите допустимое падение напряжения.
2. Выберите слои, ширины кольца и stripes, число полос и шаг их расположения.
3. Оцените сопротивления характерных путей от точек подключения питания к нагрузкам.
4. Учтите сопротивления vias и ограничения по току в проводниках и переходах.
5. При недостаточном запасе измените ширины, шаг, количество полос или vias.
6. После размещения ячеек выполните проверку связности, анализ IR Drop и проверку токовых ограничений.
7. При необходимости скорректируйте сеть и повторите анализ.

## 5.8. Placement blockage

Placement blockage ограничивает размещение стандартных ячеек в заданной области. Он не удаляет rows и не запрещает автоматически прокладку проводников.

![Скриншот: placement blockage](doc/images/placement_blk.PNG)

### Routing blockage и отличие от placement blockage

**Routing blockage** — область с ограничением трассировки на выбранном слое или наборе слоёв металла. При его создании необходимо задать границы и слои. Он не запрещает размещение стандартных ячеек и не удаляет rows или уже существующие проводники.

| Объект | Назначение | Удаляет rows? |
| --- | --- | --- |
| Hard placement blockage | Запрещает размещение стандартных ячеек внутри области | Нет |
| Routing blockage | Ограничивает прокладку проводников на указанных слоях | Нет |
| Cut row | Удаляет ряды или их участки в заданной области | Да |

Для routing blockage проверьте настройки применения ограничения к сигнальной и специальной трассировке в используемой версии инструмента. Наличие такого объекта само по себе не означает удаления или разрыва уже созданной сети питания.

### Создание и проверка blockages

1. Выберите нужный тип объекта: placement или routing blockage.

2. Задайте прямоугольную область координатами нижнего левого и верхнего правого углов.

3. Для placement blockage выберите тип **hard**; для routing blockage укажите выбранный разрешённый слой металла.

4. Создайте объект через GUI либо командой.

5. Выберите созданный объект и проверьте его тип, границы и, для routing blockage, слои и параметры ограничения.

6. Освойте изменение границ и удаление blockage. При выполнении задания на 5 включите эти операции во второй Tcl-скрипт.

В задании на 5, кроме hard placement blockage **A–B**, создайте routing blockage **C–D**. Координаты приведены в разделе задания. На защите покажите свойства обоих объектов и слой routing blockage.

Удаление placement blockage и восстановление rows — разные операции: удаление blockage не восстанавливает вырезанные ряды.

# 6. Подготовка Tcl-скрипта и работа с .cmd

## 6.1. Команды, переменные и source

Скрипт — текстовый файл с последовательностью команд. Команды выполняются в контексте текущей базы проекта. Переменные позволяют вынести параметры отдельно от действий.

Пример синтаксиса Tcl, без создания объектов Innovus:

```tcl
# Параметры демонстрационного примера; значения иллюстративные.
set core_width 100.0
set core_height 80.0
set x0 10.0
set center_x [expr {$x0 + $core_width / 2.0}]
puts "Центр core по X: $center_x"
```

Команда `source` выполняет команды из указанного файла в текущей сессии:

```tcl
source ../flow_scripts/flow.innovus.floorplan.tcl
```

Путь — пример; используйте фактический путь своего проекта. Если файл содержит определения процедур, их подключение не заменяет вызовы этих процедур.

## 6.2. Что такое файл .cmd

Файл `.cmd` используется как источник записанных команд сессии, если запись команд включена в используемом окружении. Это помогает найти команды, соответствующие выполненным действиям.

**Дополнить:** фактическое имя и расположение `.cmd`, условия записи GUI-действий и пример содержимого для используемой версии.

![Скриншот: файл .cmd и команда, полученная после действия в GUI](doc/images/innovus_cmd_history.png)

История команд не является автоматически готовым маршрутом: она может содержать команды просмотра, выделения, неудачные попытки и действия, зависящие от уже изменённой базы.

Чтобы подготовить скрипт:

1. Выполните нужную операцию на демонстрационном проекте и найдите соответствующую запись.

### Параметры кольца питания

| Обозначение на рисунке | Параметр | Как определить значение |
| --- | --- | --- |
